## Measured result

Installed `/Applications/LibreOffice.app/Contents/MacOS/soffice`, version `LibreOffice 26.8.0.3 bce0998afefdbc355585ca324285661a2170ba77`, was run headless with separate new PDF and ODT profiles. Exact argv, profile paths, stdout/stderr and version are in `system-run.json`. The first sandbox attempt exited 1 without output; an approved elevated rerun produced both artifacts. This is the installed system binary, not bundled LibreOfficeDev alpha.

Page2 renders **200009**, and its subsequently saved presentation contains 200009. The initial presentation still contains 200000 and is byte-identical to page1's presentation subtree. Thus, for this deliberately divergent EXP control, the measured importer uses the StarMath annotation for the constant; the previous alignment result is no longer the sole basis for that inference. No general claim about every annotation encoding or consumer follows.

Page4, imported from regenerated MathML with annotation removed, keeps all three formula rows and 200001 but loses left alignment. PDF text origins on pages1–3 are `[110.70,110.70,110.70]`pt; page4 is `[110.70,115.30,125.15]`pt (spread14.45pt). The saved page4 annotation regenerated by the importer contains no alignl, whereas pages1–3 do. The regenerated mtd `columnalign="left"` attributes therefore do not preserve this alignment in this measured presentation-only reimport. These coordinates describe extracted text origins, not glyph ink bounds.

The reimport also changes Commands grouping beyond removing alignl: `P left ( t right ) = 2000 e ^ { 0,1 t }` becomes `P { left ( t right ) = 2000 } e ^ { 0,1 t }`; `- 5000` and `- 0,03` acquire inner groups. This follows the nested mrow structure of Writer's saved presentation. The verifier now records both exact Commands and asserts that they differ even after removing alignl. String/grouping differences do not alone establish semantic inequivalence; no structural or semantic correspondence between the exported presentation and annotation is certified here. The saved presentation is not a validated reference for a serializer.

All four `system-page-*.png` pages were visually inspected: three rows, expected final constants, no visible red error marker; page4 continuation rows are indented. Human observations and the initial sandbox failure are recorded separately in `observations.json`. `verify_probe.py` checks input hashes/embedded bytes, exact archive member names (no cached preview/import state), unchanged source saved ODT hash, exact divergence, exact annotation removal, regenerated numbers/annotations, the Commands grouping difference, and PDF row coordinates. It passes. `git diff --check` passes.
